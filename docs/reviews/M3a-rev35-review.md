## 2. 发现

### R35-1（低，隐私，原来就有）：值里有 `"`、`\` 或控制字符的秘密找不到

`docs/privacy.md` 写明：请求里出现守护进程环境里名字像秘密（KEY、TOKEN、SECRET、PASSW 等）的变量的值（至少 8 个字符），什么都不发。

`_gate` 的最后一步是这样查的：先用 `json.dumps` 把请求序列化成 `content`，再看每个秘密值是否出现在 `content.casefold()` 里。但 JSON 会转义 `"`（`\"`）、`\`（`\\`）和控制字符（`\t` 等）。值里有这些字符时，它在 `content` 里的样子和原值不同，查不到。

直接调用 `gate`，POSIX 的 `echo '<值>'`，把这个值作为秘密传进去，新旧代码一样：

| 秘密的值 | 结果 | 发出的 `command` 里有原值吗 |
|---|---|---|
| `pass1234wd` | 拒绝（"the request would carry the value of a secret environment variable"） | — |
| `pa"ss1234wd` | 送审 | 有 |
| `pa\ss1234wd` | 送审 | 有 |
| `pa<制表符>ss1234wd` | 送审 | 有 |

- 只在命令、路径或任务意图里照写了这个值、而脱敏的规则又没认出来时才有影响。这一步本来就是兜底：令牌一类的值多半只有字母、数字和 `-_`，常见的令牌写法脱敏也认得；密码里有 `"`、`\` 的不少见。
- 这一步从 M3a（`46169eb`）起就这样，和修订 35 无关。路径规范化把值改了形（`$X/…` 展开后 `\` 变成 `/`）的情形，这次没有看。
- **建议**：秘密值在 JSON 里的写法也查，即 `json.dumps(值, ensure_ascii=False)[1:-1]`；或者逐个字段查原文。先改规格（修订 36），补测试（`"`、`\`、制表符），跑变异。判决不变；会多拒绝一些请求（这时什么都不发，按 `on_failure` 处理）。

### R35-2（信息，多换，代价没写全）

规格修订 35 写的代价：
- R34-1：只写了 `-C:\\server…`、`/C:\\server…`，以及几个字母的名字加冒号（`path:`、`Temp:`）；
- R34-3：只写了 `--ox/c/Users/<名字>/y`。

实际多换、或者换法变了的还有下面几种。都只是请求里的文字；新代码没有一种比旧代码多带用户名。

1. **粘着选项后面紧接盘符写法**（本会话发现）：`gcc -IC:\\server\share\<名字>\inc`、`cl /FoC:\\server\…`、`gcc -LC:\\server\…`。
   - `-IC:` 整个合"粘着的选项可以带一个 `:`"，按冒号选项换：`command`、`args`、`flags` 是 `-IC:~\inc`。
   - 规则层读成 `-I` 加 C 盘上的路径，不是主目录。
   - 修订 34 原样，修订 33 也换。
   - 和 `C:\\server…` 一样少见，宁可多换说得过去，规格没写。
2. **兄弟目录又显示成 `~ Smith`**（子代理）：POSIX 的 `cp '-isystem/home/<名字> Smith/inc' x`。
   - 规则层的路径原文是 `-t` 的值 `em/home/<名字> Smith/inc`，切开的地方落在 `-isystem` 中间。修订 35 不切，整个词照命令全文换：空格算名字的结束，`args`、`flags` 成了 `-isystem~ Smith/inc`。修订 34 原样。
   - `<名字>(2)`、`<名字>'2`，以及 Git Bash 的 `/c/Users/<名字> Smith`，都一样。
   - `command` 两版本来就是 `-isystem~ Smith/inc`（命令全文的边界）；`args`、`flags` 现在跟它一致。修订 33 的复审 R32-2 去掉的那种多换，在这一种形状里回来了。
   - `gcc '-isystem/home/<名字> Smith/inc'`（切开的地方正好在选项末尾）两版都原样，是对的。
   - 要靠规则层把 `cp`、`mv`、`install` 的短选项拆开读 `-t` 才会这样，真实的写法里很少见。
3. **一个词里两处主目录时，换的是哪一处变了**（子代理）：Git Bash 的 `-isystem/c/Users/<名字>/a;/c/Users/<名字>\b`。
   - 修订 34：`-isystem/c/Users/<名字>/a;~\b`。
   - 修订 35：`-isystem~/a;/c/Users/<名字>\b`。命令全文的边界里，斜杠写法后面的 `\` 不算结束，第二处不换。
   - 两版都发出一次用户名。子代理的随机比对里有 966 对这样的（盘符主目录 299、UNC 主目录 667）。
4. **记录第 6 节漏了两种**：修复记录第 6 节"多换"没有列 `path:\\server…`、`Temp:\\server…`；规格写了。

- **建议**：只改文字，把 1 到 3 写进规格修订 35 的代价，记录第 6 节补上。
- 第 2 种也可以改代码：不切开时，从选项末尾切，后面那段按路径的边界换。但那段不是规则层记下的路径原文，和修订 32 定的"规则层读成路径的才用路径的边界"不一致，不建议为这么少见的写法改。

### R35-3（信息，文档）：规格几句说法不准

1. 第 331 行解释"盘符的冒号"时，例子里列了 `-C:\\server…`，而这一条的意思是盘符的冒号后面不换（两边都发现）。
   - 同一段的代价（第 336 行）说它按选项换成 `-C:~`，代码和测试也是这样。
   - 整条链路：`python -c "print(r'-C:\\server\share\<名字>\x')"` 发出的是 `-C:~\x`。子代理另试了 `make -C:\\…`，发出的是 `make -C:~\x`。
   - 应把 `-C:\\server…` 从例子里拿掉，或注明"粘着选项时按选项换"。
2. "按路径的边界多找到的只有一种，结果相同"（规格第 344 行、`home_begins_before` 的注释）在修订 35 的新条件下不成立（子代理）。
   - 多了一种：`-`、`--` 开头的选项粘着斜杠写法，后面跟 `\`，切开的地方落在选项中间。
   - 例：Windows 的主目录，`-isystem/c/Users/<名字>\x` 从 `-isyst` 切开；UNC 主目录的 `--ox//server/share/<名字>\x` 从 `--o` 切开。命令全文的边界找不到，路径的边界找到。
   - 结果仍然相同：切开时路径原文里认不出主目录，不切时命令全文也不换，两种都原样（`_word` 在子代理的 381,915 次调用里都一样）。
   - 应改成"多找到的是斜杠写法后面跟 `\` 的几种，切不切结果相同"。
3. "不变：……送不送审"（第 346 行、记录第 1 节、提交说明）有例外（子代理）。
   - 秘密环境变量的值落在主目录的写法里（如值就是用户名、至少 8 个字符）、`paths` 里又没有它时，修订 34 拒绝送审，修订 35 换成 `~` 之后送审。
   - 直接调用 `gate`：`/OUT:\\server\share\<名字>\a.exe`、`api_key:\\…`、`FileSystem::\\…`，值为 `testuser`，三条都是修订 34 拒绝、修订 35 送审。请求里没有那个值，方向是对的。
   - 只会在注释、字符串里出现：真实的 `link /OUT:…` 调用，`paths` 里带着小写的用户名，照样拒绝。
4. 第 335 行说修订 34 的 `link /OUT:\\server\…` 的请求"`command`、`args`、`flags` 带着用户名"，但 `link` 的请求没有 `flags`（`null`），只有 `gcc '-o:…'` 一类有（子代理）。

- 第 332 行"选项本身仍要在词的开头"只对一个字母的冒号选项有影响：`x/OUT:\\server…` 不合粘着选项的条件，但 `T:` 不是盘符的冒号，照样换；`x/F:\\server…` 不换（子代理）。不算错，不用改。
- **建议**：和 R35-1、R35-2 一起改文字。
