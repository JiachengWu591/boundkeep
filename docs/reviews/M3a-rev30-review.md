## 2. 发现

### R30-1（低）：主目录换成 `~` 时不看边界

`_Places.word` 不分大小写地查主目录这段文字，查到就换成 `~`，不看后面跟的是什么。

| 探针 | 命令里写的 | 请求的 `command` 和 `args` | 请求的 `paths` |
|---|---|---|---|
| `home-prefix` | `Copy-Item README.md <主目录>x\a.txt` | `~x\a.txt` | 完整的路径，不在主目录下（对） |
| `home-prefix-bash` | `cp README.md <主目录，正斜杠>2/a.txt` | `~2/a.txt` | 同上 |
| `home-plain`（对照） | `<主目录>\Desktop\a.txt` | `~\Desktop\a.txt` | `~/desktop/a.txt` |

- 在 Bash 里，`~x` 是用户 `x` 的主目录，`~2` 是目录栈的第 2 项。模型看到的文字和实际运行的不是一回事。规格和 `docs/privacy.md` 说"一字不改，只把主目录写成 `~`"，这里多改了。
- `paths` 是对的：它按路径的键比，看边界。
- 不让任何东西多放行。真实的主目录形如 `C:\Users\<名字>`，同一台机器上另有 `C:\Users\<名字>.CORP`、`C:\Users\<名字>2` 这样的目录时才会遇到。
- **建议**：只在主目录后面是路径分隔符、引号、空白、行尾，或者 shell 的分隔符时才换。更直接的说法是：后面的字符不能出现在文件名里。

### R30-2（低，隐私）：主目录的另几种写法不换

`_Places.word` 只认两种写法：`C:\Users\<名字>` 和 `C:/Users/<名字>`。

| 探针 | 写法 | 请求的 `command` | `args` | `paths` |
|---|---|---|---|---|
| `home-gitbash` | `cp README.md /c/Users/…/home/Desktop/a.txt` | 原样，带用户名 | 原样，带用户名（M3a 起就这样） | `~/desktop/a.txt` |
| `home-gitbash-comment` | 注释里写 `/c/Users/…/home` | 原样，带用户名 | 不在词里 | 不在路径里 |
| `home-escaped` | `python -c "open('C:\\Users\\…\\home\\.ssh\\x')"` | 原样，带用户名 | `~\.ssh\x`（Bash 的双引号把 `\\` 读成了 `\`） | 不在路径里 |
| `home-fwd`、`home-ps-fwd`、`home-upper`、`home-ps-comment`（对照） | 正斜杠、大写、PowerShell 注释 | `~…` | `~…` | `~…` |

- Claude Code 在 Windows 上的 Bash 工具（Git Bash）常写 `/c/Users/<名字>/…`。这样的命令送审时，用户名会发给 LLM 服务。
- 规格 §9.2 说"和其他字段一样，主目录写成 `~`"，`docs/privacy.md` 说"只把主目录写成 `~`"。两处都没有说这是尽力而为，也没有说哪些写法不换。
- 修订 30 之前，`args` 里的 Git Bash 写法就带用户名。修订 30 把注释、字符串里的写法也带了出去。
- **建议**：
  - 加上 Git Bash 的写法（`/<小写盘符>/…`）和双反斜杠的写法，同样看边界（R30-1）；
  - 规格和隐私文档写明这是尽力而为，列出不换的写法：环境变量展开之后的值、URL 编码、拆开拼接的字符串等。

### R30-3（信息）：拒绝的字符比文档写的多

发送闸门用 `str.isprintable()` 判断字符，词、路径、全文都一样。它把 Unicode 里"其他"和"分隔符"两大类都算作不可打印，只有 ASCII 空格例外：

| 字符 | 类别 | 结果 |
|---|---|---|
| `U+00A0` 不换行空格、`U+3000` 全角空格 | Zs | 拒绝 |
| `U+2028` 行分隔符 | Zl | 拒绝 |
| `U+E000` 私用区 | Co | 拒绝 |
| `U+1FAE9`（Unicode 16.0 的 emoji） | 对 Python 3.12 的 Unicode 15.0 来说是未分配（Cn） | 拒绝 |
| `U+200D` 零宽连接符（`U+1F468 U+200D U+1F4BB` 这类组合 emoji 里都有） | Cf | 拒绝（文档里的"零宽字符"） |
| `U+1FAE8`（Unicode 15.0 的 emoji）、`🧪`、中文、全角标点 | So、Lo、Po | 照常送审 |

- 规格 §9.2、`docs/privacy.md`、`docs/threat-model.md` 都写的是"控制字符或格式字符"，没有提到空格类、私用区和未分配的码位。
- 修订 30 起注释里的字符也算。注释里有上表前五行字符的命令，有后端时现在直接问，原来送审。探针 6 条，修订 30 之前都送审，现在都不送审：全角空格、不换行空格、`U+2028`、私用区、组合 emoji、Unicode 16.0 的 emoji。
- 语料里没有这样的命令：记录里那 16 次变化，是 NUL 和像秘密的文字。
- **建议**：行为不改。不换行空格看起来是空格，在 shell 里却不是分隔符；私用区和未分配的码位，各处显示得不一样。只把文档改准确："控制字符、格式字符、ASCII 空格以外的空白、私用区和未分配的码位"。
