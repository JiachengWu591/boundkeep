## 2. 发现

### R36-1（低，隐私，原来就有）：PowerShell 切换到环境变量的目录后，后面的路径带着展开的值

`send_gate.py` 开头的注释、`docs/privacy.md` 第 14 行、`docs/threat-model.md` 第 37 行都说：用守护进程的环境展开过变量的路径按原文发（`$GITHUB_TOKEN/x`），不发展开值。

路径本身是这样做的：`Get-Content $env:SECRETS_DIR\x.txt` 的 `paths` 是 `$env:SECRETS_DIR\x.txt`。但 PowerShell 的 `Set-Location`、`Push-Location`、`cd` 的目标里有 `$env:名字` 时，规则层用环境展开它，得到新的工作目录（`normalize/event.py` 的 `_cd_target`）。同一个调用里后面命令的相对路径按这个目录解析，它们自己没有"展开过变量"的标记，`_path` 显示的是 key，也就是展开之后的值。

整条链路，Windows，PowerShell 工具，新旧代码一样（`rv36r_agentcheck.py`）：

| 命令 | 环境变量 | 请求里第二个命令的 `paths` |
|---|---|---|
| `Set-Location $env:DB_PASSWORD; python gen.py` | `DB_PASSWORD=pa\ss1234wd` | `<project>/pa/ss1234wd/gen.py`，送审 |
| `Set-Location $env:SECRETS_DIR; python gen.py` | `SECRETS_DIR=D:\vault\prod01` | `d:/vault/prod01/gen.py`，送审 |
| `Push-Location ${env:API_TOKEN}; python gen.py` | `API_TOKEN=tk\9f8e7d6c5b` | `<project>/tk/9f8e7d6c5b/gen.py`，送审 |
| `Set-Location $env:DB_PASSWORD; python gen.py` | `DB_PASSWORD=pa/../ss1234wd` | `<project>/ss1234wd/gen.py`，送审（只剩后一段） |
| 同上 | `DB_PASSWORD=pass1234wd.` | `<project>/pass1234wd/gen.py`，送审（去掉了尾随的点） |
| 同上 | `DB_PASSWORD=pass1234wd`（对照） | 拒绝：值照原样在 `paths` 里，被秘密检查找到 |
| `Set-Location $env:WORK_DIR; python gen.py` | `WORK_DIR=pa\ss1234wd`（名字不像秘密） | `<project>/pa/ss1234wd/gen.py`，送审 |

- 也就是说，秘密检查只在值经过路径规范化不变时才兜得住。值里有 `\`、`//`、`..`、尾随的点或空格时，读得出来的另一种样子随请求发出。名字不像秘密的变量，展开值本来就照发，和文档"不发展开值"也不一致。
- Bash 不这样：`cd "$DB_PASSWORD" && python3 gen.py` 的工作目录算作不知道，后面的 `gen.py` 原样发（三条整条链路，POSIX 和 Git Bash）。
- 要后端，要模型那边的调用里有切换目录到环境变量、后面又有相对路径。真实的密码、令牌拿来当目录很少见；被注入的提示词可以故意这样写，把值送到 LLM 服务那边。API 密钥一类的值多半只有字母、数字和 `-_`，照原样在 key 里，会被找到。
- 子代理从读代码推测：解析到盘上链接或 8.3 短名的路径（`event.py` 里另外两处造路径引用的地方）也可能丢掉"展开过变量"的标记。这次没有量。（2026-11-18 补，修订 37 时量了：链接的目标原来就带这个标记，推测不对；通配符匹配到的文件原来不带，`Get-Content $env:SECRETS_DIR\*.txt` 发出匹配到的文件在盘上的路径。见 `docs/reports/M3a-rev36-review-fixes.md`。）
- **建议**：先改规格（修订 37），再改代码，判决不变：
  - 由展开过变量的工作目录解析出来的路径，也带"展开过变量"的标记，按原文发；
  - 或者 `send_gate` 遇到这样的路径就不发。

  前一种请求里看得到 `gen.py`，看不到它在哪里；后一种多拒绝。补整条链路的测试（上表几条，加上名字不像秘密的那条）。

### R36-2（信息，原来就有）：几种改了形的写法找不到，文档没写

规格修订 36 写的"仍找不到"只有两种：命令里转义着写的、规则层改了形的写法（路径的 key 里 `\` 写成 `/`）。下面几种也找不到，新旧代码一样（`rv36r_agentcheck.py`）：

1. **任务意图里的控制字符和多个空格**：会话存意图时（`session/intent.py` 的 `extract_intent`），不可打印的字符先变成空格，连着的空白并成一个。值是 `ab<制表符>cd1234ef`、`ab<换行>cd1234ef`、`ab<两个空格>cd1234ef` 时，意图里存的、发出的都是 `ab cd1234ef`。
2. **任务意图截断**：意图最多 300 个字符，截断的地方落在秘密值中间时，只发前一段加 `…`：`zq9X7v3K1m8P2r4w` 只发出 `zq9X7v3K1m8P2`。这和"把值拆开的找不到"是同一类。
3. **命令里换一种写法的 Windows 路径**：值是 `D:\keys\gcp.json`，命令写 `D:/keys/gcp.json`（PowerShell）、`/d/keys/gcp.json`（Git Bash）、`D:\keys\.\gcp.json`，都送审，`paths` 里是 `d:/keys/gcp.json`。规格的代价写的是"照写这个路径的不发"，这句没错；但"仍找不到"里只写了规则层改的形，没写命令自己换的写法。
4. **环境里的值带尾随换行**：值是 `tok3n9f8e7d6c5b` 加 `\n`（或 `\r\n`）时，命令里照写 `tok3n9f8e7d6c5b`，请求里没有那个换行，找不到，送审。不带换行的对照被找到。PowerShell 用 `Get-Content -Raw` 读文件设变量时会这样；Bash 的 `$(cat 文件)` 会去掉尾随换行。

- **建议**：第 1、2、3 种写进"仍找不到"。第 4 种可以改代码：值去掉两头的空白之后（仍至少 8 个字符）也找，放进修订 37。第 1 种也可以改：意图里另找值的空白并成一个空格之后的写法。两种都会多拒绝一点，复审不强求。

### R36-3（信息，文档）：修订 36 几句说法不准

1. **"命令里转义着写的找不到"说宽了**（规格修订 36 段落、§11、`docs/privacy.md` 第 19 行、记录第 1 节和第 6 节、提交说明；两边都发现）。整条链路，值是 `pa"ss1234wd`、`pa\ss1234wd` 或带制表符（`rv36r_escapes.py`）：
   - shell 自己去掉的转义，规则层拆出来的词里就是原值，新代码找到、旧代码带着值送审（10 条）：
     - Bash：`echo "pa\"ss1234wd"`、`echo pa\"ss1234wd`、拼起来的引号 `'pa"'ss1234wd`、`echo "pa\\ss1234wd"`、`$'pa\x22ss1234wd'`、`$'pa\tss1234wd'`，Git Bash 的 `echo "pa\"ss1234wd"`；
     - PowerShell：反引号转义 ``"pa`"ss1234wd"``、双写引号 `"pa""ss1234wd"`、``"pa`tss1234wd"``。
   - PowerShell 单引号里双写的 `'pa''ss1234wd'`（值是 `pa'ss1234wd`），两版都找到：值里没有要转义的字符。
   - 真正找不到的是程序自己解释的转义，命令全文和词里都不是原值（4 条，两版都送审）：`printf 'pa\x22ss1234wd'`、`printf 'pa\tss1234wd'`、Bash 的 `python3 -c 'print("pa\"ss1234wd")'`、PowerShell 的 `python -c "print('pa\"ss1234wd')"`。
   - 规格举的 PowerShell 例子，找不到的原因写得不全：Windows PowerShell 5.1 不把 `\"` 当转义，规则层把词拆成 `print('pa\` 和 `ss1234wd)"` 两个，哪个字段里都没有原值，不只是"命令文字里是 `pa\"ss1234wd`"。
   - 应改成：shell 的引号和转义去掉之后照写在词里的找得到；交给程序自己解释的转义（`printf`、各种语言的字符串）找不到。
2. **任务意图里的控制字符**（子代理）：记录第 6 节第 1 条和提交说明的"代价"都说，值里有控制字符、又照写在任务意图里的，现在不送审。其实意图存的时候控制字符已变成空格（R36-2 第 1 种），两版都送审，请求里是改了形的值。任务意图里，修订 36 多拒绝的只有带 `"`、`\` 的值（先过 `extract_intent` 再过 `gate`：`ab"cd1234ef` 旧代码送审，新代码拒绝）。
3. 提交说明的"代价"没有写第 1 条的那 10 种：它们也是修订 36 新拒绝的。方向是对的，送出去的更少。

- **建议**：和 R36-1、R36-2 一起改文字。修订 36 的记录加带日期的更正。提交说明不能改，在下一份记录里说明。

1. `test_a_secret_value_that_is_a_windows_path_is_found_in_the_command`：`args` 里也带着值，没有一条测试的值只在 `command` 里（比如在注释里）。检查是对整个请求做的，换哪个字段都一样，影响不大。
