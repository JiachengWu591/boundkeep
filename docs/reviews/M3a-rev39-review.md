## 2. 发现

### R39-1（低，判决偏松，修订 13 起）：名字以点结尾的联接，通配符匹配到时只看去掉点的读法

布局（`rv39r_dotjunc.py`），事件的 `cwd` 和项目相同：
- JR：`kq.` 是指向 `secretsz` 的目录联接（`secretsz` 里有 `.env`），旁边的 `kq` 是普通目录，里面只有 `a.txt`；
- JR0：同样的联接 `kq.`，没有 `kq`。

| 工具 | 命令 | 三份代码（新、`98d4ff5`、`1499e14`）都是 |
|---|---|---|
| Bash | `rg made ???`、`tar -czf o.tgz ???`、`cp -r ??? b` | 灰色：没有后端时问，有后端时送审、被放行 |
| Bash | `grep -r made ???` | 问（`ask-shell-read-outside-project`） |
| PowerShell | `rg made ???`、`Copy-Item -Recurse ??? b` | 灰色，同上 |
| Bash、PowerShell | `rg made kq.`、`tar -czf o.tgz kq.`、`Copy-Item -Recurse kq. b`（对照，直接写名字） | 拒绝（`no-secret-read`） |

实际会读到（Git Bash 保留尾随点）：
- JR、JR0 里 `grep -rl MADE ???` 列出 `kq./.env`，`cp -r ??? b` 拷出 `.env`；`tar` 把联接存成链接，不读里面的文件。
- PowerShell 5.1 去掉尾随点：JR 里 `Copy-Item -Recurse ??? b` 拷出的是 `kq` 里的 `a.txt`；JR0 里找不到 `kq`，报错。

原因：
- 直接写 `kq.` 时，`_refs_one` 除了去掉点的 key，还调用 `_kept_forms`：用 `\\?\` 加原文求盘上的真实路径，`kq.` 是联接，解析到 `secretsz`，另算一份，往下找，找到 `.env`。
- 通配符匹配到的 `kq.` 只经过 `_glob_refs` → `_resolved_forms`：只有去掉点的 key（`…/kq`）和它在盘上解析出来的样子，没有 `_kept_forms`。JR 里 `kq` 是普通目录，往下找什么都没有。
- JR0 里更早一步：`paths._expand_glob` 最后用 `os.path.lexists` 核对匹配到的路径，Win32 去掉尾随点，`kq` 不存在，`kq.` 这个匹配被丢掉，动作只带"通配符没展开"的灰色标记。

- 子代理在 `372bfa1`（修订 13）上量的一样；在 `bede21d`（修订 12）上直接写名字和通配符都是灰色。修订 39 没有改变它，但 §8 补的"通配符匹配到的也一样"说宽了。
- 前提：项目里要有名字以点结尾、指向要保护文件的链接。PowerShell 5.1 的 `New-Item -ItemType Junction -Path '\\?\…\kq.'` 就能建（实测；子代理量到 `cmd /c mklink /J` 会去掉尾随点）。被注入的 agent 可以先建好再用通配符。
- **建议**：通配符匹配到的、只差读法的路径，也算保留尾随点的那种读法（匹配到的名字本身就是盘上的原名），和直接写名字一样调用 `_kept_forms` 或等价的做法；`_expand_glob` 核对存在时用 `\\?\` 写法，不让 Win32 去掉尾随点。补 JR、JR0 的测试，钉住拒绝。

实际会读到：
- K 里 Git Bash 的 `ls -a ???/` 列出 `.env`；`tar -cf - ??? | tar -tf -` 列出 `kq./`、`kq./.env`；`grep -rl MADE ???` 列出 `kq./.env`；`cp -r ??? backup` 拷出 `.env`。
- PowerShell 5.1 的 `Copy-Item -Recurse ??? backup` 去掉尾随点，找不到 `kq`，报错；`Copy-Item -Recurse -LiteralPath '\\?\…\kq.' b` 拷出了 `.env`（`\\?\` 写法只有一种读法）。

原因：
- 往下找（`_native_dir`）用的是 key 换成 `\` 的路径，key 去掉了尾随点，Win32 打开的是 `kq`。
- `_kept_forms` 用 `\\?\` 求盘上的真实路径，`kq.` 不是链接，解析出来还是 `kq.`；规范化之后 key 又去掉了点，和已有的一份相同，不另算一份。所以保留点的那种读法只在它通向别处时才往下找。
