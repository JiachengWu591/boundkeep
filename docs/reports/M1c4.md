# M1c-4 验收报告：会话 scratchpad（`allow-session-scratchpad`）

里程碑：让 Claude Code 每个会话自己的 scratchpad 里的文件读写不再被问。日期：2026-10-21。实现者没有提交、没有推送，没有碰 `~/.boundkeep`、`~/.claude`（测试只用临时 `BOUNDKEEP_HOME`），没有执行任何被测命令（只做归一化）。

## 1. 结论

**加了匹配字段 `path_in_scratchpad` 与一条 default 专有的 allow 规则 `allow-session-scratchpad`（default 现为 69 条规则，strict 仍是 53 条、唯一的 allow 仍是 `read-inside-project`）。** 只有当前会话、本机守护进程临时目录之下的 `<temp>/claude/<slug>/<session id>/scratchpad` 里的 `Write` / `Edit` / `MultiEdit` / `NotebookEdit` / `Read` / `Grep` / `Glob` 变成 allow；shell 工具没有任何放宽；所有 deny / ask 规则照样最严者胜。差分检查（9716 次条目运行，两台假机器、未信任与受信任）：**所有已有条目的判决 0 个变化**，新条目里唯一的变化是正例从 gray 变 allow。`emit_allow` 仍是 `false`，allow 只是"无决定"。

与任务书不同的地方都是**更严**，列在第 8 节，需要你确认。

## 2. 设计（实际标记什么）

- 事件的 `session_id` 必须存在且是 UUID（`^[0-9a-fA-F]{8}(-[0-9a-fA-F]{4}){3}-[0-9a-fA-F]{12}$`，`fullmatch`）；缺失、空白、`..`、`*`、带分隔符、过长、尾随换行、花括号、非十六进制都不标记。
- 根键 `<tmp>/claude/<恰好一段>/<session_id>/scratchpad`。`<tmp>` 取自归一化层拿到的 `env` 与 `home`（`paths.temp_dir_text`）：Windows 取 `TEMP`、否则 `TMP`、否则 `%LOCALAPPDATA%\Temp`、否则 `<home>\AppData\Local\Temp`（变量名不分大小写，取第一个非空的，不因值不可用而落到下一个；同名不同大小写又取值不同算有疑问：不标记）；POSIX 取 `TMPDIR`、否则 `/tmp`。临时目录必须是本机盘符路径或 POSIX 绝对路径，不得是 UNC / 设备 / 相对 / 含变量或通配符 / 带怪异拼写的。不用 `tempfile`，不看真实机器；`policycli._FAKE` 加了 `TEMP`（Windows：`C:\Users\testuser\AppData\Local\Temp`）与 `TMPDIR`（POSIX：`/tmp`）。
- `claude`、`scratchpad` 两段在 Windows 风格里不分大小写、POSIX 里区分；会话 id 一段始终不分大小写。scratchpad 目录本身也标记（`Grep` / `Glob` 的 `path`）。上级（临时目录、`claude`、slug、会话目录）、别的会话、`scratchpad2`、`scratchpad.x`、`..` 折叠后走出去的、不确定的路径都不标记。
- **键入形式与链接解析形式都要在里面。** 一个路径产生的每个 `PathRef`（字面的、`resolve_on_disk` 之后的）各有一个 `in_scratchpad`（`model.PathRef.in_scratchpad: bool = False`），匹配器要求每个都是 true。解析形式对照**解析后的临时目录**（惰性、每个请求最多一次磁盘查询、只在路径走到那一步时）：scratchpad 里指向别处的符号链接 / junction、scratchpad 目录或它的上级目录本身是指向别处的链接，都让解析形式落到根之外，不标记；临时目录本身是链接时按解析后的目录比较；`TEMP` 写成 8.3 短名字时按解析后的长名字比较。
- 实现：`normalize/paths.py`（`temp_dir_text`、`Scratchpad`、`scratchpad_for`、`scratch_plain`）、`normalize/event.py`（`_Ctx.scratch`，`_make_ref` 设置 `in_scratchpad`，`_plain_operands`）、`normalize/model.py`（`PathRef.in_scratchpad`）、`policy/schema.py`（`Match.path_in_scratchpad: _TrueOnly`，加入"只列不碰路径的工具时路径条件无意义"的检查，`PolicyTest.session_id`）、`policy/matcher.py`（至少一个路径且每个都 `in_scratchpad`；explain 明细行 `path_in_scratchpad: every path is inside the session scratchpad`；失败方向与 `path_inside_project` 相同，allow 里出任何问题都算不匹配）、`policycli.py`（`_run_one(..., session_id=None)`，默认仍是非 UUID 的 `policy-test`，`explain` 在路径行加 `in_scratchpad`，`boundkeep test` 把 `tests:` 条目的 `session_id` 传下去）。单独写 `path_in_scratchpad` **不**满足"allow 规则必须点名工具或程序"。

## 3. 规则文本

```yaml
  - id: allow-session-scratchpad
    tool: [Write, Edit, MultiEdit, NotebookEdit, Read, Grep, Glob]
    match:
      path_in_scratchpad: true
    action: allow
```

放在 `allow-project-file-writes` 之后（完整注释在 `policies/default.yaml`）。strict 没有。

## 8. 与任务书不同的地方（都更严，需要你确认）

1. **路径层做过"翻译"的写法不标记。** 只有这些改写算"同一个文件的不同写法"：NTFS 流名、一个尾随点、`\\?\` / `\\.\` / `\??\` 前缀、解析后的形式。MSYS（`/c/Users/...`）、Cygwin（`/cygdrive/c/...`）、WSL（`/mnt/c/...`）、本机管理共享（`\\localhost\c$\...`）、展开后的 `~` 与变量（`%TEMP%\...`、`~\AppData\...`）一律不标记：路径层为了保护而把它们译成了 `c:/...`，但文件工具并不会这样理解它们（`/c/Users/x` 在 Windows 上会落在 `C:\c\Users\x`），对 allow 不能照译。真实的 Claude Code 路径是绝对的字面 Windows 路径，用不到这些写法。
2. **文件与搜索工具的路径操作数里带 `* ? [ ] { } < > | "` 的不标记**（任务书只说"通配符"）：Windows 名字里不可能有它们，POSIX 里有也可能被某个工具当成模式（`[id]`、`{a,b}`）。Grep 的 `glob: "*.py"` 拼出来的探测名不算操作数，所以 `Grep path=<scratchpad> glob=*.py` 仍是 allow。
3. **临时目录的怪异拼写不要**：`TEMP` 带 `\\.\` 前缀、通配符、变量、相对路径、UNC、尾随点或同名不同大小写取值不同，都当没有 scratchpad。8.3 短名字写的 `TEMP` 会解析成长名字再比较；但**路径本身**用短名字拼写（`TESTUS~1`）的不认（路径层认为它不确定）。
4. **`\\.\C:\...` 与 `\??\C:\...` 被标记**（与已有的 `\\?\` 同一处理，是同一个文件）；`\\.\GLOBALROOT\...`、`\\.\pipe\...` 不标记。
5. **任务书"大小写变体"里的"会话 id 大写 / 小写"我按设计当作正例**（会话 id 始终不分大小写）；错的会话 id 才是反例。
6. **同一会话 id 但不同 slug 的目录也算**（slug 是"恰好一段"，任意名字）：这符合设计，需要在临时目录下有 `claude/<任意>/<本会话 id>/scratchpad`，那是同一用户进程能做的事。
7. **`PolicyTest` 加了可选的 `session_id`**（`policy/schema.py`），否则内嵌 `tests:` 没法测这条规则（任务书要求每条 allow 规则有内嵌正反例）。`_run_one` 的默认 `session_id` 仍是 `policy-test`（非 UUID），所以所有已有测试里没有路径会被标记。
8. `measure_ask_rate.RunOne` 现在是 `Callable[..., str]`：条目带 `session_id` 才作为关键字参数传下去，四个参数的旧写法仍然可用。

## 9. 残余风险

- **agent 可以在 scratchpad 里写脚本，而运行它仍由 exec 规则判定**（灰色，会问）。写和运行是两次调用，规则看不见它们的关系（与 `allow-project-file-writes` 同类；M3 的污染标记才是收紧办法）。
- **守护进程的临时目录可能与 Claude Code 的不同**（例如守护进程以别的环境变量启动）：那样规则不适用，一切保持原状，不会更宽松。
- 恶意项目不能用名字伪造（根必须在守护进程的临时目录之下）；同一用户的其他进程能在临时目录下建同名目录，在"同一用户的进程"信任边界之内。
- 解析在判定时做一次，之后有人把目录换成链接，规则看不见（与项目内规则的磁盘解析同一限制）。符号链接版本的真实磁盘测试在本账号上跳过（不能建符号链接），junction 版本跑了。
- 没有在真实 Claude Code 里验证 `session_id` 与 scratchpad 目录名一致、守护进程环境与 Claude Code 的 `TEMP` 一致：这是任务书给出的已验证事实（审计日志里的例子），本实现按它做；真实会话验收仍要手工做一次（让 agent 在 scratchpad 写文件，`boundkeep log` 看判决）。
