## 2. 改了什么

`normalize/event.py`：
- `_resolved_forms`：盘上解析出来的那一份也带上 `extra_reasons`。通配符调用它时传的是 `glob-match`，别处不调用。
- `_CWD_READINGS`（新）：`drive-relative`、`rooted-current-drive`，路径层给这两种不算相对、key 却取了工作目录的路径或盘符的路径记的原因。
- `_refs`：
  - 路径是相对的，或者带 `_CWD_READINGS` 里的原因，而所用的工作目录是展开变量得来的，这一组都加标记；
  - 去重的键里不算 `variable-expanded`：只差这个标记的两份合成一份，留带标记的那一份。

`audit/send_gate.py`：只改了 `_hidden_match` 的注释。

## 3. 取舍

- **R37-1 在规则层补原因，不改 `send_gate`**：复审给了两种修法，另一种是 `_hidden_match` 藏起"原文不是命令里那个词"的路径。`send_gate` 不知道命令里的词是哪个，规则层知道哪一份是通配符匹配到的。
- **R37-2 去重时留带标记的那一份，不把事件的 `cwd` 换成 key**：后一种从根上让两份工作目录合成一份，但事件的 `cwd` 原文在规则层很多地方用到，牵涉面大。代价：和修订 36 比，这样的路径按原文发（`gen.py`），不再是 `<project>/gen.py`。同一个 key 能从一个没展开过变量的工作目录得到，值本身就不是只藏在变量里；按原文发更保守，和修订 37 的选择一致。
- **R37-3 只看第一个工作目录**：`D:x`、`\x` 本来就只按第一个可能的工作目录解析（`_refs` 里不相对的路径只用 `cwds[:1]`），所以只看它。所用的工作目录不在同一个盘时，key 里没有它，也加标记，按原文发，没有坏处。
- **R37-4 不改代码**：要跨调用记住哪个目录是展开变量得来的，得放进会话状态（SQLite），是设计上的取舍。宿主会不会把工作目录留到下一次调用也没有量。

## 6. 代价和残余

1. 展开出来的目录正好是事件的工作目录时（`Set-Location $env:PROJ_DIR`、`Set-Location $PWD`），后面的相对路径只发原文，和修订 36 比模型看到的少了（`gen.py`，不是 `<project>/gen.py`）。
2. 事件里没有 `cwd`、切换到展开变量的目录之后，`D:x`、`\x` 只发原文。Claude Code 的事件都带 `cwd`，碰不到。
3. 仍有的（规格修订 38 写明）：标记只在一个调用之内。宿主把工作目录留到下一次调用时，下一个事件的 `cwd` 就是展开出来的目录，后面的路径带着值。真实宿主里没有量。
4. 递归读找到的要保护的文件（`_scan_refs`）不带标记，key 里有值；它们都命中 deny / ask 的读规则，不送审。规则对某个目录有例外、例外里又有要保护的名字的情形没有搭。
5. 仍找不到（规格修订 37、38 写明）：交给程序自己解释的转义；改了形的路径；任务意图里改了形的；值两头是 BOM、零宽空格的；拆开、编码过的。
6. 只在有后端时起作用。模型那边的效果没有量（M3b）。PowerShell 7、Linux、macOS 上没有量。这次修复没有复审，真实宿主里没有跑。
