## 1. 结论

  - 在整个词里按命令全文的边界找主目录的写法，没有一处从前面那段里开始；
  - 前面那段以 `/` 开头时，路径原文不以 `/` 开头。

  `/c/Users/<名字>/x`、`/cygdrive/c/…`、`/mnt/c/…`、`-C:\Users\<名字>\x`、主目录 `/root` 时的 `/root/tmp/x` 都整个照命令全文换成 `~`。`/srv/home/<名字>/x` 原样（另一个路径）。
- R33-3 已修：UNC 带反斜杠的两种写法单独用一个左边界，前一个字符不能是字母、数字、下划线，也不能是 `.`、`\`、`/`、`~`、`:`。`C:\\server\share\<名字>\x`、`.\\server\…` 原样；`=`、`(`、引号、`,` 后面，和粘着 `/I`、`-L` 的照旧换。
- R33-4：只改规格的文字，行为不变（测试钉住了）。

## 2. 改了什么

只改了 `audit/send_gate.py`：
- `_PATH_AFTER_DRIVE`、`_PATH_AFTER_WINDOWS`、`_PATH_AFTER_POSIX`：后面是 `,`、`;` 也算结束；后两个还加了 `:`。
- `_BEFORE_UNC`（新）：UNC 带反斜杠写法的左边界，粘着的选项记在 `unc_option` 里。`_home_pattern` 把"盘符或反斜杠开头"的写法分成盘符的和 UNC 的两组，各用各的左边界，右边界照旧。
- `_option_of`（新）、`_tilde`：从 `drive_option`、`unc_option`、`slash_option` 里取粘着的选项。
- `_Places.home_begins_before`（新）：一个词里，主目录的某种写法（命令全文的边界）是不是从某个位置之前开始。第一版也按路径的边界找，变异测试里"只用命令全文"、"只用路径"两个都存活；推下来按路径的边界找不出更多（见第 5 节），改成只用命令全文，补了一条测试抓"只用路径"。（2026-11-17 更正："找不出更多"字面上不成立：Windows 的主目录，`/` 开头的前面那段是斜杠写法第一段的一部分（`/cyg` 加 `drive/c/Users/<名字>\x`）时，只有路径的边界把后面的 `\` 算作结束。切不切结果相同。见修订 34 的复审 R34-2。）
- `_word`：以路径原文结尾、前面那段合选项形状的词，再看两条，都满足才切开：主目录的写法不从前面那段里开始；前面那段以 `/` 开头时，路径原文不以 `/` 开头。不满足的，接着试短一些的路径原文，都不行就照命令全文换。

## 3. 取舍

- **A，不是 B**（R33-1）：只改规格文字（B）的话，用户名仍会随 `args`、`flags` 发出，只是 `paths` 里本来也有。按 A 改，一串路径在 `args`、`flags` 里不再带用户名。代价是名字里带 `,`、`;`、`:` 的兄弟目录多换。这种名字很少见，一串路径在构建命令里常见，宁可多换。
- **`paths` 不改**：`-Wl,` 后面的整段读成项目下的一个相对路径，是规则层的读法。改它要动规则层和判决，不在这次的范围里。
- **两条都要**（R33-2）：只看"主目录从前面那段里开始"，挡不住 `/srv/home/<名字>/x`：`/srv` 后面的 `/home/<名字>` 不是主目录的写法的开头（前一个字符是 `v`）。只看"`/` 开头的前面那段不接 `/` 开头的路径"，挡不住 `-C:\Users\<名字>\x`。
  - 代价：Git Bash 里粘着 `/` 选项的斜杠写法（`/I/c/Users/<名字>/inc`），`args` 里不换。修订 32 也这样，命令全文也不换。
- **UNC 的左边界加 `:`**（R33-3）：斜杠写法的左边界不排除 `:`（`PATH=/home/<名字>:…` 后面那段要换）。UNC 写法前面是 `:` 时，几乎都是盘符后面多写了一个反斜杠（`C:\\server…`），是 C 盘上的目录。（2026-11-17 更正：不准。冒号选项 `/OUT:`、`/LIBPATH:`、`-Path:` 和 PowerShell 的 `FileSystem::` 后面接的就是 UNC 路径，排除所有的 `:` 比修订 33 少换。见修订 34 的复审 R34-1，修订 35 只排除盘符的冒号。）
- **`\\?\UNC\` 不认**（R33-4）：它和 `\\?\C:\…` 对称，加一种写法就够。但它只在文字里出现（真去访问是网络访问，规则层问），很少见，这次只写进规格。

## 6. 代价和残余

1. 改的只是请求里的文字，判决、送不送审不变。
2. 多换：
   - 名字里带 `,`、`;`、`:` 的兄弟目录（R33-1 的代价）；
   - 路径词里照写的转义 UNC 写法；
   - URL 里的 UNC 正斜杠写法（`http:~/x`）。

   命令全文多换的写法，见规格修订 32 到 34。
3. 不换：
   - Git Bash 里粘着 `/` 选项的斜杠写法；
   - `\\?\UNC\…` 等 UNC 的几种写法（规格修订 34 列了）；
   - 修订 33 列的几种。

   用户名会随之发出。
4. `paths` 里规则层的读法没有改：`-Wl,` 后面的整段、`-DCMAKE…` 的值读成项目下的相对路径，带着用户名。
5. 只在有后端时起作用。模型那边的效果没有量（M3b）。PowerShell 7、Linux、macOS 上没有量。UNC 主目录只用编出来的路径量过。这次修复没有复审，真实宿主里没有跑。
