## 1. 结论

- R34-1 已修：UNC 带反斜杠的两种写法前面，不粘选项时只排除盘符的冒号（一个字母加 `:`，字母前面不是字母、数字、下划线）；粘着的选项可以带一个 `:`。
  - `link /OUT:\\server\share\<名字>\a.exe`、`/LIBPATH:`、`cl /Fe:`、`findstr /F:`、`robocopy /LOG+:`、`-Path:`、`FileSystem::`、`Microsoft.PowerShell.Core\FileSystem::` 后面的主目录换成 `~`，`command`、`args`、`flags` 都是。
  - `C:\\server\…`、`c:\\server\…`、`"C:\\server…`、`=C:\\server…` 仍原样（C 盘上的目录）。
  - 代价：`-C:\\server…`、`/C:\\server…` 这种一个字母加冒号、又像选项的，按选项换成 `-C:~`。
- R34-3 已修：切开的地方落在主目录写法粘着的选项中间时不切，整个词照命令全文换。`cp -isystem/home/<名字>/inc`（规则层的路径原文是 `-t` 的值 `em/home/<名字>/inc`）的 `args`、`flags` 是 `-isystem~/inc`，和 `command` 一致。
  - 代价：修订 33 的测试钉的 `--ox/c/Users/<名字>/y`（规则层读成 `--o` 加相对路径 `x/c/Users/<名字>/y`）是同一种形状，现在是 `--ox~/y`。宁可多换。
- R34-2：只改文字，行为不变（测试钉住了）。
- 规则层、判决、送不送审、请求格式和提示词都不变，改的只是请求里的文字。

## 2. 改了什么

只改了 `audit/send_gate.py`：
- `_DRIVE_COLON`（新）：盘符的冒号，`(?<!(?<!\w)[A-Za-z]:)`。
- `_BEFORE_UNC`：粘着的选项那一支后面可以带一个 `:`（`(?:--?|/)[A-Za-z]+:?`）；另一支的前一个字符不能是字母、数字、下划线、`.`、`\`、`/`、`~`，再加 `_DRIVE_COLON`。修订 34 是排除所有的 `:`。
- `_Places.home_begins_before`：一处主目录的写法（命令全文的边界）从切开的地方之前开始，并且它粘着的选项不是正好在切开的地方结束，就算。修订 34 只看主目录本身是不是从切开的地方之前开始。注释更正了"按路径的边界找不出更多"。
- `_word`、`_home_pattern`、`_Places.word` 的注释：写到修订 35。

## 3. 取舍

- **粘着的选项带 `:`，不只是排除盘符的冒号**（R34-1）：只排除盘符的冒号的话，`/OUT:`、`-Path:`、`FileSystem::` 都换了；但一个字母的冒号选项（`findstr /F:`）的 `F:` 也像盘符的冒号，不换。让粘着的选项可以带 `:`，`/F:` 就按选项换。
  - 代价：`-C:\\server…`、`/C:\\server…` 也按选项换。它们读成路径时是 `C:` 后面的 `\server\…`，不是主目录；这种写法很少见，宁可多换。
  - 盘符的冒号前面是引号、`=`、`(`、空格或词的开头时，照修订 34 不换（`C:\\server…` 是 C 盘上的目录）。
- **R34-3 照命令全文**：规则层把短选项拆开读成 `-t` 加相对路径，命令全文读成粘着 `-isystem` 的主目录。规则层的读法里没有主目录，命令全文的读法里有；`command` 已经是 `~`，`args`、`flags` 跟着它，宁可多换。
  - 代价：`--ox/c/Users/<名字>/y` 这种规则层读成 `--o` 加相对路径的，现在显示成 `--ox~/y`。修订 33 的 `test_the_longest_path_text_that_fits_is_taken` 用的就是这个例子；它要钉的是"有几个路径原文能对上时取最长的"，改用 `--ox1/c/…`（`1` 不是字母，`--ox1` 不是粘着的选项）仍钉得住，`--ox` 这个例子搬到新文件按新行为钉住。
- **R34-2 不改代码**：`\\?\UNC\…` 粘着选项时送审、`java -cp` 在 Windows 上不送审，都是规则层的读法；"按路径的边界多找到的那一种"结果相同。

## 6. 代价和残余

1. 改的只是请求里的文字，判决、送不送审不变。
2. 多换：
   - `-C:\\server…`、`/C:\\server…` 这种一个字母加冒号、又像选项的（R34-1 的代价）；
   - 规则层读成选项加相对路径、命令全文读成粘着选项的主目录的，如 `--ox/c/Users/<名字>/y`（R34-3 的代价）；
   - 修订 34 记录里列的几种（名字带 `,`、`;`、`:` 的兄弟目录，路径词里照写的转义 UNC 写法，URL 里的正斜杠 UNC 写法）。
3. 不换：
   - `\\?\UNC\…` 等 UNC 的几种写法（规格修订 34 列了）；粘着选项时会送审，用户名随 `command`、`args`、`flags`、`paths` 发出（规格修订 35 更正）；
   - Git Bash 里粘着 `/` 选项的斜杠写法；
   - 修订 33、34 列的几种。
4. `paths` 里规则层的读法没有改：`/OUT:…` 读成当前盘上的路径、`-Wl,` 后面的整段读成项目下的相对路径、`cp` 的 `-t` 值，都带着用户名。
5. 只在有后端时起作用。模型那边的效果没有量（M3b）。PowerShell 7、Linux、macOS 上没有量。UNC 主目录只用编出来的路径量过；真实的 `link.exe`、`cl.exe` 没有跑。这次修复没有复审，真实宿主里没有跑。
