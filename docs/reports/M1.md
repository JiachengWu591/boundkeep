## 1. 结论

**通过（自动验收、Linux 容器验证、真实 Claude Code 冒烟与你的手工验收都通过；一个遗留条件见下）。** M1 把 M0 的占位判定换成了真正的"归一化 → 规则 → 取最严"：自写的保守 Bash 解析器、程序知识表、路径与域名规范化、策略 schema 与规则引擎、`boundkeep test` / `explain`，以及判决到 hook 输出的映射。`pytest` 5488 通过、72 跳过、0 失败；`ruff`、`mypy --strict` 无告警；`normalize` 与 `policy` 包的行覆盖率 97% 到 100%；`boundkeep test` 在两个平台上通过默认策略的 88 条与 strict 策略的 50 条；真实 Claude Code 2.1.292 的 M1 冒烟 11 项检查 0 失败。

## 4. 与计划的偏差

- **没有用 bashlex**：你批准了自写（它是 GPLv3+）。工作量比计划大，所以解析器与知识表是整个 M1 最大的部分（`bash.py` 约 1500 行、`programs.py` 约 1900 行有效代码）。
- **Action 列表**：规格原来是一个 Action；M1 澄清为一条命令行里每个简单命令一个 Action，合并取最严（你批准了，已写入规格 §7）。另外 `Action` 多了 `wrappers`（被剥掉的 sudo / env 等；allow 规则不会匹配带包装器的动作）。
- **协议新增 `allow` 决定**（只有 `emit_allow: true` 时才会发；旧客户端遇到会因严格校验降级为 ask，方向安全），没有升协议版本号。
- **首次出现的 M0 缺陷被审查发现并修了**：M0 的审计日志用带读权限的句柄追加，在 Windows Defender 实时扫描下每次 20 到 80 ms（M0 的延迟只测了客户端进程，没测守护进程的写入）。M1 改成只写句柄，`Daemon.handle` 从 p50 约 21 ms 降到约 1.5 ms；`latency_ms` 现在不含自己那次写入，另有 `prev_audit_ms`。
- **新增能力超出提示词的清单**：`init` 把 home 固定进 hook 参数（M0 决定项 #3，你选了放 M1）；`--reset-policy`；决定在线程池里带期限地跑，防止一个敌意命令卡死整个闸门（审查发现 7 KB 的 `cd src && cd src …` 链能卡住事件循环 10 秒，15 KB 要 40 多秒）；`boundkeep test` / `explain`；`doctor` 的策略、home、`CLAUDE_CONFIG_DIR` 检查。
- **默认策略比规格示例大得多**：规格给了 7 条示例，实现者与审查者补成 34 条（凭据存储、历史、agent 自己的状态、持久化、git 破坏性操作…）。理由都在注释里，但这是实质的策略内容，请你抽看。
- **PowerShell 一律灰色**（按提示词，M1b 才做），所以规格示例里"PowerShell `Remove-Item -Recurse -Force C:\` → deny"的测试暂时写成 `expect: gray` 并注明 M1b。
- **做法**：四个并行实现者（路径、解析器、程序与域名、策略）→ 我自己写组装层与管线 → 四个只读的对抗审查者（解析器与组装、路径与 glob 与域名、策略语义、性能与集成）共报告约 60 条 → 四个修复者按文件分工修复，每项先写复现。修复期间遇到一次会话额度限制，四个修复者被打断，之后全部续跑完成，我核对了状态。
- **没做**：Git Bash 的实机验证（本机没有）；`bypassPermissions` 与 `auto` 模式的验证（需要一次性环境）。

## 6. 已知问题与局限（已知无法处理的写法）

每条都会进灰色（ask）或被规则过度匹配，不会变成 allow；下面是"仍然看不清"的清单。

| 写法 | 为什么看不清 | 现状 |
|---|---|---|
| **所有 PowerShell 命令** | M1b 才做 AST 归一化 | 一律灰色，enforce 下每条都问 |
| 别名、函数定义、`IFS`、`PATH` 的改动，同一行里先定义后用 | 不跟踪 shell 状态 | `alias` / 函数定义行灰色；`IFS` / `PATH` 只记在 env 里 |
| `ln -s ~ /tmp/h; cat /tmp/h/.aws/credentials`：链接在审查时还不存在 | 不跟踪同一行里创建的链接 | 灰色 |
| `tar czf x ~`、`grep -r password ~`、`cp -r ~ /tmp`：读一个**受保护路径的祖先目录** | 规则按具体路径匹配，没有"递归读祖先"的匹配能力 | 灰色（只有读受保护路径本身才 deny）。这是设计缺口，建议 M2 之前补一个 `recursive` 标记 |
| 通过 `tar -x` / `unzip` / `rsync -a` / `git clone` 写进受保护目录，成员不详 | 归档成员在运行时才知道 | 灰色（有名字的成员会被列出并 deny） |
| 通配符展开只列举磁盘上存在的前 64 个，花括号最多 64 个结果 | 防止指数膨胀与卡死 | 超限或目录不存在时保持不确定、灰色 |
| `$(...)`、算术与数组下标注入（`let y=x` 里 `x='a[$(cmd)]'`）、`PS4`、`mapfile -C`、`enable -f`、交互程序的 shell 逃逸（vim `-c`、sqlite3 `.shell`、psql `\!`…） | 这些代码路径藏在语义里 | 能识别的已灰色；`less` / `man` 的分页器命令、ftp / sftp / ed 的 stdin `!` 不处理 |
| 未识别的包装器与运行器（`valgrind`、`perf`、`faketime`…）后面的真程序 | 选项语法各异 | 作为"运行器"灰色，不剥；未知程序的参数里出现已知程序名（`program-in-arguments`）也灰色 |

| `\\?\` 命名空间里尾随的点与 `..` 是字面的，而 key 会去掉它们 | 只影响 allow 侧、没发现攻击价值 | 记录在案，未修 |
| `Grep` 在目录上用宽泛的 `glob`（`*`）可能读到被 ripgrep 默认跳过的隐藏文件 | 不知道 Claude Code 的 Grep 是否加 `--hidden` | 显式写出名字（`glob=.env`）会被 deny；宽泛的 glob 只看目录 |
| 上传到白名单主机（`curl -d @file https://github.com`、`git push` 到攻击者的 fork）、`WebSearch` 的查询里带数据、读环境变量（`printenv`） | 规则层看不出意图 | 灰色，要等 M3 的 LLM 审计 |
