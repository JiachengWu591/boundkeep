## 3. 取舍

- **放进 `_INFO_REASONS`，不在 `_native_dir` 里单独去掉**：复审给了两种。规则层对路径（`PathRef`）调用 `reading_only` 的只有 `_native_dir`。`_INFO_REASONS`、`reading_only` 的其余用处，看的都是路径层的结果（`NormPath`），本来没有这个原因：`_cd_target`、`Grep` 工具的基准目录、`resolve_on_disk`、`_refs_one` 的盘上形式。所以两种现在效果一样。放进 `_INFO_REASONS`，原因的含义只写在一处，以后别处对路径判断"只差读法"时也对。
- **R38-3、R38-4 不改代码**（复审的推荐）：
  - R38-3 不会多发出东西，只是模型看到的少了。要改得分辨"key 能从没展开过的工作目录得到"的匹配，是设计上的取舍。
  - R38-4 只会多问。

## 6. 代价和残余

1. 判决变严：通配符匹配到的、名字带尾随点、空格或流名的目录，现在往下找；里面有要保护的文件就拒绝，原来是灰色。往下找要花扫描预算。
2. R38-3（规格修订 39 写明）：展开出来的目录正好是事件的工作目录时，通配符在项目里匹配到的文件一个都不发，模型只看到通配符。
3. R38-4（规格修订 39 写明）：经过目录联接、8.3 短名、带尾随点的值到达事件的工作目录时，同一个目录仍算两份，路径多的调用问。
4. 仍有的（规格修订 37、38 写明）：
   - 标记只在一个调用之内；
   - 递归读找到的要保护的文件（`_scan_refs`）不带标记，它们都命中 deny / ask 的读规则，不送审（2026-11-21：修订 40 起，起点展开过变量的，找到的文件带上起点的标记）；
   - 秘密值的几种写法仍找不到。
5. 没有量的：
   - ripgrep 没装，实际读到什么用的是 PowerShell 5.1 的 `Copy-Item` 和 Python 的 `os.listdir`；
   - PowerShell 7、Linux、macOS；
   - 全量里 `'done'; Get-Date` 那一次为什么判成灰色（第 5 节），没有查到；
   - 这次修复没有复审，真实宿主里没有跑；
   - R38-1、R38-2 没有后端时也起作用，模型那边的效果没有量（M3b）。
