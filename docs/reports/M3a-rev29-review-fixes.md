## 1. 结论

- Bash、PowerShell 的调用，发给模型的请求多了一个字段 `command`：命令全文，整段发送，主目录写成 `~`。请求的 `schema` 改为 `boundkeep.audit-request/2`，系统提示词改为版本 2。
- O-7 已修：复审里读脚本自身全文的写法，请求里现在都有那段注释、常量或条件。
- R29-1 已修：条件里报错的比较运算，请求里现在有条件的文字。
- 全文超过 4000 个字符、带控制字符或格式字符、经过脱敏会变（带着像秘密的文字）时，不发。
- 规则层不变。没有后端时判决级别不变，送不送审的范围也没有放宽。

## 2. 改了什么

只改了三个文件：`audit/send_gate.py`、`audit/prompt.py`、`audit/prompts/audit_system.md`。流水线、审计器、归一化、规则都没动。

- **全文从哪里来**：每个 shell 动作本来就带着原始命令行（`Action.command_text`，原来只给审计日志和金丝雀规则用）。发送闸门直接从动作里取，所以不用从流水线一路往下传。
  - 一次调用的所有动作带的是同一段文字。取不到，或者各个动作的文字不一样，就不发。
  - 工具名是 `Bash` / `PowerShell`，或者动作带着命令文字，两者有一个就算 shell 调用。
- **怎么发**：放在 `tool` 后面、`actions` 前面。主目录换成 `~` 的做法和词一样（不分大小写）。
- **不发的情形**（都按 `on_failure` 处理）：
  - 超过 `MAX_COMMAND_CHARS`（4000）个字符；
  - 有制表符、回车、换行之外的控制字符或格式字符；
  - 全文经过脱敏会变；
  - 任何一个词经过脱敏会变。词的脱敏和全文的脱敏读法不同（一个按词，一个按行），词里被认出的秘密，全文里不一定认得出；词又都在全文里，所以只要有一个词带着秘密，这条命令就不发。
  - 整个请求 16000 个字符的上限、跨字段的秘密、秘密变量的值，这些检查原样保留，现在也覆盖全文。
- **系统提示词**（版本 2，哈希 `00d3f2c6…`，版本 1 的哈希仍在 `VERSIONS` 里）：加了一条，说明 `command`：这才是实际运行的内容；`actions` 是规则层的读法，可能漏掉注释、只打印的字符串、条件里的文字、`switch` 的标签；要读全文；读自身全文（`$__claudeCodeScript`、`$MyInvocation`、`$BASH_EXECUTION_STRING`、`/proc/self/cmdline`），或者用注释、字符串、报错信息拼出代码或路径的命令，算混淆执行。
- **缓存**：键是发送内容的哈希，现在包含全文。只差一段注释的两条命令是两个问题。

## 3. 取舍

- **上限 4000**：先在语料上量（`tests/corpus` 和评测集，不含留出集；Bash 在两个平台上各跑一次，共 4906 次判决）。今天会送审的 2025 次里，命令最长 472 个字符，p99 是 122；加上全文之后，请求最长 2591 个字符。超过 2000 个字符的命令有 16 次，都已经由规则判掉或者本来就不送审。所以 4000 留了很大余地，整个请求 16000 的上限不用动。
- **带秘密就不发，而不是脱敏后发**：
  - 原来词里的秘密是脱敏之后照常发送的。
  - 全文不能这样做：脱敏的模式会整段吞掉文字，比如私钥块从 `BEGIN` 一直吞到 `END`。吞掉的部分模型看不到，这又回到了 O-7。
  - 代价：`curl -H 'Authorization: Bearer …'` 这类命令原来脱敏后送审，现在直接问。脱敏器也把名字像秘密的变量写成 `名字=值` 的文字当作秘密：语料里 15 次判决（`git log -n "$SECRET_TOKEN=src"`、`echo token=$X_TOKEN` 这类，都在 `tests/corpus`）原来是这个词脱敏后送审，现在直接问（第 4 节）。原来模型看到的本来就是 `$SECRET_TOKEN=[REDACTED]`，看不全。
- **原来"不送审"的情形一条都不放宽**：全文进了请求之后，here-document、赋值、修订 28、29 的 `unshown` 等本来可以放宽。但这要先知道真实的模型看了全文会怎么判，所以等 M3b 再定。here-document 的正文因此仍然不离开本机。
- **其他工具不变**：Write 的内容、Edit 的新旧文本照旧不发，也不带 `command`。

## 6. 代价和残余

1. **请求变长**：全文和 `actions` 里的词大部分重复。语料里送审的请求，中位数由 390 个字符到 426 个，最长 2572。
2. **有后端时直接问的多了几种**：超过 4000 个字符的 shell 命令；注释或字符串里有控制字符的（语料里 `Write-Output a<NUL>b` 原来送审，模型看到的是 `a b`）；带着像秘密的文字的（`curl -H 'Authorization: Bearer …'`，以及名字像秘密的变量写成 `名字=值` 的，如 `echo token=$X_TOKEN`）。语料里今天会送审的 2025 次判决，有 16 次改为直接问。
3. **模型那边的效果没有量**：评测只跑规则层（`rules-only`、`rules+taint`），指标不受影响；模型看了全文之后判得怎样，要等 M3b 接上真实后端。
4. **"不送审"的情形没有放宽**：全文在请求里之后，其中一部分本可以放宽；这次没有放宽。
5. **全文由攻击者写**：和参数一样，是不可信的数据。提示词说了它是数据，不是给模型的指令；这一点在真实模型上没有量。
6. PowerShell 7、Linux、macOS 上没有量。这次修复没有复审，真实宿主里没有跑。（2026-11-15：复审见 `docs/reviews/M3a-rev30-review.md`；真实宿主的检查已加进 `scripts/smoke_claude_m3a.py` 的 readings 一段，使用者运行，26 项 0 失败，代码是修订 31 的，见复审报告第 4 节的后记。）
