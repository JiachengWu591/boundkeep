## 1. 结论

- R31-1 已修：粘在长选项后面的主目录（`-isystem/home/<名字>`、MSVC 的 `/Fo<主目录>\…`），以及后面带一个点的 `<主目录>.\…`，都换成 `~`，选项和点留着。
- R31-2 已修：
  - 命令全文：`{`、`[`、`]` 不再算名字的结束；斜杠开头的写法（`/home/<名字>`、`/c/Users/<名字>`），`\` 也不再算。`<主目录>{2,3}`、`<主目录>[23]`、Bash 的 `<主目录>\2` 原样发送。
  - 规则层整个读成一个路径的词：只有分隔符和词的末尾算结束。`'<主目录> Smith\notes.txt'` 在 `args` 里原样。

| 建议 | 实际 | 原因 |
|---|---|---|
| 命令全文去掉 `{ } [ ]` | `}` 留着 | PowerShell 里 `}` 结束一个词（实测 `& {Write-Output aaa}`）；Bash 里 `{/tmp,<主目录>}` 展开之后就是主目录 |

| 尾随的点：点后面是分隔符、空白或行尾 | 点后面是本来就算结束的字符 | `Get-Content '<主目录>.'` 的点后面是引号，按建议不换。只对盘符开头的写法：Git Bash 里 `<名字>./` 是另一个名字（实测） |

## 2. 改了什么

只改了 `audit/send_gate.py`：
- 把主目录写成 `~` 的那一步（`_Places.word`）分成两套边界，由 `_home_pattern` 生成：
  - 命令全文、不是路径的词、`flags`：`_TEXT_AFTER_DRIVE`、`_TEXT_AFTER_SLASH`；
  - 规则层整个读成一个路径的词、展开过变量的路径原文：`_PATH_AFTER_DRIVE`、`_PATH_AFTER_WINDOWS`、`_PATH_AFTER_POSIX`。
- **后面**，命令全文：文字末尾、空白、`/`，或 `` ' " ` ; | & ( ) < > , : } `` 之一；盘符开头的写法再加 `\`。盘符开头的写法，这些字符前面可以多一个 `.`。
- **后面**，路径词：文字末尾，或分隔符（Windows 的主目录 `\`、`/`，POSIX 的主目录只有 `/`）；盘符开头的写法再加 `:`，前面可以多一个 `.`。
- **前面**：
  - 不变的部分：盘符开头的写法，前一个字符不能是字母、数字、下划线；斜杠开头的写法，前一个字符不能是字母、数字、下划线、`.`、`/`、`\`、`~`。
  - 选项：`-` 或 `--` 后面跟一个或几个字母，盘符开头的写法还认 `/` 后面跟字母。选项本身前一个字符不能是字母、数字、下划线、`.`、`/`、`\`、`~`、`-`。
  - Python 的 `re` 不支持变长的后行断言，选项写成可选的命名组（`drive_option`、`slash_option`），换的时候留着（`_tilde`）。
- `_action`：`args` 里和某个路径原文相同的词按路径的边界换；`flags` 经过主目录的替换（R31-5）。
- `_path`：展开过变量的路径原文按路径的边界换。
- 认的写法（`_home_forms`）、大小写（`_caseless`）、在原文上找，都不变。

## 3. 取舍

- **命令全文仍会多换**：主目录后面是引号、空白、反引号、`(`、`)`、`,`、`:`、`}` 时换成 `~`；这些字符在引号里或 Bash 的词中间，却是名字的一部分。如 `'<主目录> Smith\…'`、`<主目录>'2'`、``<主目录>`echo 2` ``、`'<主目录>(2)'`。命令全文没有解析过，分不出引号里外；不换的话，`cd "/home/<名字>"`、`ls ~ /tmp`、`PATH=/home/<名字>:…` 这类常见写法会把用户名发出去。规格照实写了，路径以 `paths` 为准。
- **Git Bash 里加了引号的 `\`**：`'/c/Users/<名字>\notes.txt'` 读的是主目录，但命令全文分不出有没有引号，不加引号的 `\2` 是转义（兄弟目录）。按复审的建议不再换，用户名随 `command` 发出，`args`、`paths` 是 `~`。修订 31 换它；修订 31 之前不认 Git Bash 的写法。这种写法在 Git Bash 里少见。
- **`foo-I/home/<名字>` 不再换**：修订 31 只看前两个字符，它也换；它其实是相对路径。选项要在词的开头，`./-I…`、`a/Fo…` 也不换。
- **选项只认字母**：`-I2/home/<名字>` 不换。`-IxC:\Users\<名字>`（包含目录 `xC:\…`，相对路径）会被换：分不出 `-Ix` 是不是一个选项。这种写法少见。

## 6. 代价和残余

1. 改的只是请求里的文字，判决、送不送审不变。
2. 命令全文多换的几种写法，见第 3 节。
3. MSVC 的 `/I`、`/Fo` 粘着主目录时，规则层把 `/IC:\Users\<名字>\inc` 读成当前盘上的 `\IC:\Users\<名字>\inc`，`paths` 里是 `c:/ic/users/<名字>/inc`，带着用户名。这是规则层的读法，`paths` 按键显示，没有改。
4. PowerShell 里的 `/c/Users/<名字>/…`：PowerShell 5.1 读成当前盘的 `\c\Users\<名字>\…`（实测），不是主目录。规则层按 Git Bash 的写法读成主目录，记为 `msys-translated`；请求里和 `paths` 一样显示成 `~`。没有改。
5. 不换的写法见规格修订 31、32，用户名会随之发出。
6. 只在有后端时起作用。模型那边的效果没有量（M3b）。PowerShell 7、Linux、macOS 上没有量。这次修复没有复审，真实宿主里没有跑。（2026-11-16：复审见 `docs/reviews/M3a-rev32-review.md`，低危 2 条、信息 2 条。）
