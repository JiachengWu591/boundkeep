## 4. 与计划的偏差

- **新增模块**：计划里没有单列 `ownhook`、`hookcmd`、`console`、`protocol`、`paths`、`claude_settings`、`settings_io`、`install`、`fsperm`、`ipc/winsec`、`ipc/endpoint`；它们是把"hook 客户端要轻、`init` 要原子、权限要回读"拆开后的自然边界，不改变设计。事件里多了一个 `ping`（只给 `doctor` 用，不写日志）。
- **E18 更正**：M0a 记录"文本模式读 stdin 会在 gbk 下崩溃"。M0 里实测不是崩溃，而是 stdin 的 `errors=surrogateescape`，**悄悄读成乱码**，规则会因此匹配落空。已更正 `docs/hook-behavior.md`、规格与 M0 提示词，测试改为断言转发文本逐字一致。更正单独成一个提交（见第 8 节）。
- **ruff 的 `PLW1514`**（`open()` 必须写 `encoding`）是预览规则，已启用（`preview = true`，`explicit-preview-rules = true`）。
- **规格的 5 处补充**（你在批准计划时已同意，已写入规格）：`init` 默认项目级、手动启动常驻进程、审计日志只记提示词长度、ConfigChange 对无法解析的 settings 失败即关闭、`command` 从不裁剪（裁大内容与 `tool_response`，请求上限 8 MiB）。
- **实现方式**：叶子模块（脱敏与日志、winsec 与 fsperm、策略、settings 与 install）由并行的实现者完成，再由对抗式审查者复现问题、修复者先写复现再修；核心路径（hook 客户端、IPC、常驻进程、CLI）我自己写。完成后又让三个独立审查者各自只读审查核心模块并复现，发现已修复并补了回归测试（第 5 节）。
- **冒烟的花费超过计划**：你批准"几次、几美分"，我实际跑了约 8 次真实调用做第一遍（含一次因判定方法空洞而重做），修复后又完整重跑 2 遍，累计约 0.4 美元。冒烟的第一版曾用"副作用文件有没有出现"来判断命令是否执行，那是空洞的检查（`-p` 下写文件命令被 Claude Code 自己的权限系统拒绝，与 boundkeep 无关），已改为看 Claude 输出里的 `tool_result`，并有对照场景证明检测有效。
- **没做**：POSIX 宿主验收；POSIX 以外的平台；VS Code 扩展里的自动化（只能手工验收）。Docker 里的 POSIX 测试在手工验收之后补做了（见第 5 节），`pytest-cov` 也已按你的决定加上。
- **删除**：我的冒烟实验目录 `E:\bk-m0-*`（5 个）已删；`E:\bk-lab*` 已经不存在。
