## 1. 结论

- R32-1 已修：UNC 的主目录（`\\server\share\<名字>`）算 Windows 的主目录。认 `\\server\share\<名字>`、转义过的 `\\\\server\\share\\<名字>` 和 `//server/share/<名字>`；前两种和盘符开头的写法一样，后面的 `\` 和单个尾随点都算结束。`\\server\share\<名字>\notes.txt` 又换成 `~\notes.txt` 了。
  - 实际影响比复审写的还小：UNC 主目录下的路径是网络访问，规则层直接问（`net-allowlist`），不送审。会送审的只有注释、字符串这类文字里出现的 UNC 主目录。
- R32-2 已修：一个词以这个动作某个路径的原文结尾，前面是选项（`--directory=`、`-isystem`、`-Path:`、`/Fo`、`-Wl`），后面那段按路径的边界换，选项原样。`--directory=<主目录> Smith/src`、`-isystem<主目录> Smith/inc` 在 `args`、`flags` 里原样（兄弟目录）；`--directory=<主目录>/src` 照旧换成 `--directory=~/src`。
- R32-3、R32-4：只改规格的文字，行为不变（测试钉住了）。
- 规则层、判决、送不送审、请求格式和提示词都不变，改的只是请求里的文字。

## 2. 改了什么

只改了 `audit/send_gate.py`：
- `_home_forms`：以两个反斜杠开头的主目录是 UNC 的主目录，给出三种写法：`\\server\share\<名字>`、`\\\\server\\share\\<名字>`（标为"盘符或反斜杠开头的 Windows 写法"）、`//server/share/<名字>`（斜杠写法）。盘符和 POSIX 的主目录不变。
- `_home_pattern`：有"盘符或反斜杠开头"写法的主目录是 Windows 的主目录，路径词里它的斜杠写法也认 `\`。逻辑没改，UNC 的主目录现在落在这一边。
- `_OPTION_PREFIX`、`_word`：`args` 和 `flags` 里的每个词，先找这个动作的路径原文（长的先试）：
  - 和某个原文一字不差，按路径的边界换（修订 32 起就这样）；
  - 以某个原文结尾，前面那段是选项（`-`、`--` 或 `/`，一个字母，再跟字母、数字、下划线或 `-`，最后可以带 `=` 或 `:`），前面那段原样，后面那段按路径的边界换；
  - 都不是，按命令全文的边界换。
- 规则层记下的路径原文，实测是这个词的结尾一段：`--directory=` 后面的值、`-isystem` 后面的值、`-Wl,-rpath,…` 里的 `,-rpath,…`。`make PREFIX='…'` 规则层把整个词读成一个路径，修订 32 已经按路径的边界换。

## 3. 取舍

- **UNC 的正斜杠写法**：`//server/share/<名字>` 在 Git Bash 里也是 UNC，`\` 在不加引号时是转义，所以命令全文里照斜杠写法处理，`\` 不算结束；路径词里它是 Windows 的主目录，`\`、`/` 都是分隔符。
- **只认选项**：前面那段不是选项（`pycache_prefix=`、代码、列表）的，照命令全文的规定换，兄弟目录仍会显示成 `~ Smith`。前面是什么，词里分不清是选项还是别的，宁可只认最常见的选项形状。
- **前面那段原样**：选项名里不会有主目录，不必再换。
- **Git Bash 的尾随点**（R32-3）：MSYS 自带的程序读成另一个名字，原生程序读成主目录，两种都有，照旧不换，宁可少换；规格改成照实的说法。

## 6. 代价和残余

1. 改的只是请求里的文字，判决、送不送审不变。
2. 命令全文多换的写法，见规格修订 32、33；前面不是选项的值（`pycache_prefix=<主目录> Smith`），`args` 里也会多换。
3. Git Bash 交给原生程序的 `/c/Users/<名字>./…`、用户名带空格时的转义写法、PowerShell 里的 `<主目录>{…}`，都不换，用户名会随之发出（规格修订 33 写明了）。
4. 只在有后端时起作用。模型那边的效果没有量（M3b）。PowerShell 7、Linux、macOS 上没有量。UNC 主目录只用编出来的路径量过，没有真的 UNC 配置文件。这次修复没有复审，真实宿主里没有跑。
