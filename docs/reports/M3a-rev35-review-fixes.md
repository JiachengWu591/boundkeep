## 1. 结论

- R35-1 已修：请求序列化之后，秘密变量的值按原样的写法和 JSON 转义之后的写法都找，仍不分大小写。
  - 值里有 `"`、`\`、制表符、换行的，原来送审、请求里带着原值，现在不送审，按 `on_failure` 处理（默认策略是问）。
  - 代价：名字像秘密的变量的值是 Windows 路径时（如 `GOOGLE_APPLICATION_CREDENTIALS=D:\keys\gcp.json`），命令里照写这个路径的也不送审。POSIX 上这样的路径本来就不送审。主目录下的路径例外：主目录先写成 `~`，请求里没有原值。
  - 仍找不到：命令里转义着写的（PowerShell 的 `python -c "print('pa\"ss1234wd')"`，命令文字里是 `pa\"ss1234wd`）；规则层改了形的（路径的 key 里 `\` 写成 `/`）。
- R35-2、R35-3：只改文字，行为不变（测试钉住了）。
- 规则层和它的判决、请求格式、提示词都不变。送不送审只在 R35-1 那里变：多拒绝。

## 2. 改了什么

只改了 `audit/send_gate.py`：
- `_carries`（新）：秘密值至少 `MIN_SECRET_CHARS` 个字符时，看请求的 casefold 里有没有它的原样写法，或 `json.dumps(值, ensure_ascii=False)` 去掉两边引号之后的写法。转义的方式和请求本身的序列化相同。

- 注释：模块开头拒绝的情形、`gate` 的 `secrets`、`home_begins_before`（"按路径的边界多找到的"改成斜杠写法后面跟 `\` 的情形，两种例子）。

## 3. 取舍

- **两种写法都找，不逐个字段找原文**：发出去的就是序列化之后的文字，在它上面找最直接；转义只碰 `"`、`\` 和控制字符（`ensure_ascii=False`，别的字符原样），逐字对应，大小写折叠也逐字，所以转义之后的写法在请求里是连着的一段。
  - 原样的写法照旧也找（M3a 起的做法）：值里有 `"` 时，原样的写法只可能跨字段凑出来（`aaa", "bbb`），那时也拒绝，宁可多拒绝。
- **改了形的写法不找**：路径的 key 把 `\` 写成 `/`、命令里转义着写的，要按每种改形的方式再变换一次秘密值，复审没有建议，这次不做，规格写明。
- **R35-2 的兄弟目录不改代码**：理由见规格修订 36（从选项末尾切开后用路径的边界，那段不是规则层记下的路径原文）。

## 6. 代价和残余

1. 多拒绝：秘密变量的值里有 `"`、`\`、控制字符、又照写在命令、路径或任务意图里的，不送审，按 `on_failure` 处理（默认问，严格策略拒绝）。名字像秘密的变量的值是 Windows 路径时，照写这个路径的命令也这样。
2. 仍找不到（规格修订 36 写明）：
   - 命令里转义着写的；
   - 规则层改了形的写法（路径的 key 里 `\` 写成 `/`）；
   - 把值拆开再拼起来的、编码过的（M3a 起就这样，这一步只是兜底，前面还有脱敏）。
3. 修订 35 的几种多换（R35-2）没有改，规格修订 36 写进了代价：粘着的选项后面紧接盘符写法的，R34-3 不切开时的兄弟目录，一个词里两处主目录换哪一处。
4. 只在有后端时起作用。模型那边的效果没有量（M3b）。PowerShell 7、Linux、macOS 上没有量。这次修复没有复审，真实宿主里没有跑。
