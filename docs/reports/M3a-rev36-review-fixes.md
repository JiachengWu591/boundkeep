  - 通配符在展开过变量的目录里匹配到的文件，原文就是盘上的路径，不放进请求，只发通配符的原文。（2026-11-19 更正：经过链接时，匹配到的文件在盘上解析出来的那一份没有藏起来，原文里带着值发出；见修订 37 的复审 R37-1，规格修订 38 已修。）

## 2. 改了什么

`normalize/event.py`：
- `_Line` 记下一个调用里哪些工作目录是展开变量得来的（`expanded_cwds`）。
- `_cd_target` 另外返回目标里有没有展开过变量；`_after_cd` 据此记下：目标展开过变量的，或者目标是相对路径、而它所在的工作目录是展开变量得来的。
- `_refs` 多一个参数 `expanded_cwds`：相对路径按这样的工作目录解析时，这一组路径都带上 `variable-expanded`；一个路径的字面形式带这个标记时，它在盘上解析出来的其他形式也带上。五个按 `st.cwds` 解析路径的地方都传进去。
- 标记只加进 `reasons`，`uncertain`、`inside_project` 等都不变；`variable-expanded` 本来就是只作说明的原因（`paths._INFO_REASONS`）。

`audit/send_gate.py`：
- `_hidden_match`（新）：带 `variable-expanded` 和 `glob-match` 的路径不放进请求的 `paths`；它的原文和 key 照旧检查，有不可打印字符的照旧拒绝。数路径个数照旧算它。
- `_carries`：秘密值去掉两头空白之后的写法也找，仍要至少 `MIN_SECRET_CHARS` 个字符。
- 注释：模块开头、`gate` 的 `secrets`。

## 3. 取舍

- **按原文发，不拒绝**（使用者选的）：和展开过变量的路径本身一样处理，判决不变，不多问。
- **标记放在规则层，不在 `send_gate` 里判断**：`send_gate` 只看得到路径，不知道工作目录是怎么来的。
- **通配符匹配到的文件不发**：它的原文就是盘上找到的路径，按原文、按 key 都带着变量的值。只发通配符本身的原文。
- **盘上解析出来的其他形式也带标记**：实测时链接的目标原来就带（`resolve_on_disk` 保留了原因），保留尾随点的读法、`..` 先跟链接的读法、通配符匹配到的文件原来不带。（2026-11-19 补：这次只量了目录联接，8.3 短名是修订 37 的复审补量的，原来就带，规格那句"测过"说早了。）
- **Bash 不用另外改**：`cd "$X"` 的工作目录本来就算作不知道。路径层自己解析的 `$HOME`、`${HOME}`、`$PWD` 也算展开过变量，`cd $HOME/sub && cat a.txt` 的 `a.txt` 也只发原文；主目录本来就写成 `~`，这里只是模型看到的少了，没有为它们另开例外。
- **只补尾随空白**（使用者选的）：任务意图里控制字符存成空格的写法、意图截断、命令里换一种写法的 Windows 路径，都写进"仍找不到"，不改代码。

## 6. 代价和残余

1. 展开过变量的工作目录后面的相对路径只发原文，通配符在其中匹配到的文件不发，模型看到的少了。`$env:USERPROFILE`、`$env:TEMP` 这类常见的目录也一样，Bash 的 `cd $HOME/…`、`cd $PWD/…` 之后也一样。
2. 值没有改形、原来被秘密检查拒绝的（`Set-Location $env:DB_PASSWORD; python gen.py`，值 `pass1234wd`），现在送审，请求里没有值。（2026-11-19 补：送不送审另有两处变了，都是少发：名字像秘密、值是链接、照原样写的，通配符经过它时改为拒绝；展开出来的目录就是事件的工作目录时，路径翻倍，多的超过 16 个改为问。见修订 37 的复审 R37-1、R37-2，规格修订 38 改回送审。）
3. 秘密值两头有空白的，命令里照写去掉空白的值时不送审，按 `on_failure` 处理。
4. 仍找不到（规格修订 37 写明）：交给程序自己解释的转义；改了形的路径（路径的 key 里 `\` 写成 `/`、命令里换一种写法的 Windows 路径）；任务意图里改了形的（控制字符存成空格、截断）；拆开、编码过的。
5. 只在有后端时起作用。模型那边的效果没有量（M3b）。PowerShell 7、Linux、macOS 上没有量。这次修复没有复审，真实宿主里没有跑。
