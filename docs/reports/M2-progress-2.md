## 5. 第一次真实导入（50 条）之后的修正

你在终端里跑了 `--max 50`，50 条全部确认并入库（`eval/datasets/benign/real.jsonl`，未提交）。我看了结果（脱敏后的内容），发现：

- **没有泄漏**：个人路径、用户名、邮箱、令牌的检索全部为空。
- **意图全是“未记录”**：这 50 条来自一个子代理（复审者）的会话，整份文件都标记为 `isSidechain`，导入器只从主线程取提示，所以一条意图都没有。已修：子代理会话用它收到的任务说明作为意图，主线程的调用不受子代理说明影响。
- **样本严重偏斜**：全部来自同一个会话的 58 次调用，其中 Read 本仓库源码、反复 Write 同一个草稿脚本（`t6.py` 十几次）占了大半，另外 `--max` 让它读完第一个文件就停了。已加：`--shape-limit`（默认 3，同一种调用最多留 3 条；shell 命令按“程序 + 子命令”、文件工具按目录归类）和 `--per-file N`（每个会话文件最多取 N 条，让候选分散到多个会话）。
- **草稿路径里有真实会话 id 和项目名**（`...\claude\e--boundkeep\<会话 uuid>\scratchpad`）：不是机密，但可识别；现在项目名换成 `proj`，会话 id 换成固定的假 uuid（格式不变，策略对草稿目录的判断照旧）。

新增 6 个测试，evalkit 共 87 个通过，ruff、mypy 干净。
## 6. 第二次真实导入（本项目的会话）之后的修正

你只导入了 `E--boundkeep`：80 条，没有任何个人信息（内容全是本仓库的开发）。但统计里有 710 次“疑似密钥”丢弃，约占 992 次调用的 70%，而留下来的几乎全是 Read / Grep / Glob 这类简单调用。丢掉复杂命令会让正常样本偏向“容易放行的”，低估误报率，所以我查了原因（只看掩码后的形状，没有看内容）：

- **高熵串的误报**：长的正斜杠路径（含会话 uuid 的草稿目录）被当成一个长串，单个字母的路径段也被当成“随机”。现在：先去掉 uuid；把串按 `/`、`_`、`-` 切开，每一段如果由单词（含驼峰）组成或不超过 4 个字符就不算随机；只有含非单词段的长串才算。对全部 8832 次工具调用重算：高熵命中从 419 降到 43（其余是我的测试夹具里故意造的假密钥）。
- **URL 凭据的误报**：正则表达式文本（`://[^/\s:@]+:[^/\s@]+@`）被当成带密码的 URL；现在用户名与密码里出现反斜杠、括号、量词符号就不算。真正的 `https://user:pass@host` 仍丢弃。
- 其余的类别（AWS 密钥、GitHub 令牌、私钥头、`NAME_TOKEN=值`）未改，命中的多是我测试文件里的假样本。

新增 10 个测试（路径、标识符、会话 id 不算密钥；随机串仍算；正则文本与真凭据的区分），evalkit 共 100 个通过。
