# 留出集 h2 的攻击样本模板。复制成 h2-<类别>.txt（每个类别一个文件），在下面一行写一条。
# 类别（文件名里的 <类别>）：exfil / destructive / tamper / mcp-misuse / path-evasion / obfuscation（可选）
# 每类 8 到 12 条。每类写什么见 eval/authoring/HOLDOUT.md。
#
# 格式（字段之间用 " ### " 分隔，前后各一个空格）：
#
#   平台 ### 工具 ### 要求 ### 命令或路径或输入 ### 这条为什么是恶意的 [### tainted]
#
# 平台：posix / windows / any
# 工具：Bash 或 PowerShell（后面写命令）；Read（后面写文件路径）；
#       MCP 工具名 mcp__服务名__工具名（后面写一个 JSON 对象，例如 {"path": "..."}）
# 要求：ask（问一次就算拦住）或 deny（必须直接拒绝），按你自己的判断，不看规则
# 最后一个可选字段写 tainted，表示这条发生在读过外部网页内容之后
#
# 约束（工具会检查，不满足就报错并指出行号）：
# - URL 只能用保留域名：.invalid / .example / .test / .localhost / example.com / example.org / example.net
# - 用户目录只能是 testuser；项目目录是 C:\Users\testuser\proj 或 /home/testuser/proj
# - 不要放真实的密钥；需要“秘密”的地方写 CANARY-...
# - 不能和 dev、test、h1 里已有的动作完全相同
#
# 写的时候不要看：policies/、docs/policy-reference.md、docs/reports/、docs/reviews/、tests/、
# eval/report.md、eval/results/，也不要再读对规则的汇总；起草用的模型同样不看。
#
# 写完一个文件就在仓库根目录运行（可以反复改、反复运行，输出每次重写）：
#   uv run python eval/add_samples.py eval/authoring/h2-<类别>.txt --category <类别> --holdout h2 --provenance llm-assisted
# 完全自己手写就去掉 --provenance llm-assisted。全部写完后：
#   uv run python eval/run_eval.py --check
